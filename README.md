# مِداد — متجر أزياء رجالية

متجر عربي RTL مبني بـ Next.js 16 وPrisma 7 وPostgreSQL. يتضمن كتالوجاً وسلة محفوظة محلياً وصفحة طلب بالدفع عند الاستلام ولوحة إدارة محمية.

## التشغيل المحلي

1. استخدم Node.js 22.12+ أو 24+ ثم ثبّت الحزم:

   ```bash
   npm install
   cp .env.example .env
   ```

2. أنشئ قاعدة PostgreSQL محلية أو قاعدة Neon/Supabase، ثم حدّث `.env`:

   - `DATABASE_URL`: رابط اتصال التطبيق. يمكن أن يكون رابط pooler.
   - `DIRECT_URL`: رابط مباشر غير مجمّع لتشغيل أوامر Prisma.
   - `ADMIN_EMAIL`: بريد مسؤول المتجر.
   - `ADMIN_PASSWORD_HASH`: الهاش الناتج من الخطوة التالية.
   - `SESSION_SECRET`: سر عشوائي طويل لتوقيع جلسات الإدارة.
   - `NEXT_PUBLIC_SITE_URL`: عنوان المتجر.
   - `NEXT_PUBLIC_WHATSAPP_NUMBER`: رقم واتساب المتجر مع رمز الدولة، مثل `2135XXXXXXXX`.

3. أنشئ هاش كلمة المرور من الطرفية التفاعلية (يُستخدم bcrypt مع cost 12):

   ```bash
   npm run admin:hash
   ```

   انسخ قيمة `ADMIN_PASSWORD_HASH` المطبوعة إلى `.env`. لا تحفظ كلمة المرور نفسها في المستودع. أنشئ سر الجلسة مثلاً عبر `openssl rand -base64 32`.

4. أنشئ الجداول وحمّل بيانات البداية:

   ```bash
   npm run db:push
   npm run db:seed
   ```

   التهيئة قابلة لإعادة التشغيل: تضيف 3 فئات، 12 منتجاً مع متغيرات ومخزوناً تجريبياً، وولايات الجزائر الـ58. افتح Prisma Studio بـ `npm run db:studio`.

5. ابدأ التطبيق:

   ```bash
   npm run dev
   ```

   المتجر متاح على `http://localhost:3000` ولوحة الإدارة على `/admin`.

## الأوامر

| الأمر | الاستخدام |
|---|---|
| `npm run dev` | خادم التطوير |
| `npm run build` | بناء الإنتاج |
| `npm run typecheck` | فحص TypeScript |
| `npm run lint` | ESLint |
| `npm run test:order-state` | اختبار انتقالات حالات الطلب |
| `npm run db:push` | مزامنة مخطط Prisma مع قاعدة البيانات |
| `npm run db:seed` | إدخال/تحديث بيانات البداية |
| `npm run db:studio` | فتح Prisma Studio |

## ملاحظات أمنية وتشغيلية

- إجراء إنشاء الطلب لا يستقبل السعر أو الإجمالي من المتصفح. يعيد قراءة المنتجات والخصومات والمخزون ورسوم الشحن من قاعدة البيانات، ثم يحسب كل المبالغ داخل معاملة.
- يُخصم المخزون فقط عند تأكيد الطلب، وتُعاد الكمية عند إلغاء طلب مؤكّد أو مشحون مرة واحدة فقط.
- تحديد المعدل الحالي يعتمد ذاكرة العملية، وهو **ضعيف على البيئات عديمة الحالة/serverless** ولا يشارك العدّادات بين النسخ. استخدم Upstash Redis أو مخزناً مشتركاً مماثلاً للإنتاج.
- صور المنتجات روابط HTTPS عادية وليست مرفوعة إلى تخزين ملفات. أضف نطاقات الصور الموثوقة إلى `images.remotePatterns` في `next.config.ts`.
- لا تضع أسراراً فعلية في `.env.example` أو Git. ملف `.env*` مستثنى من Git.

## النشر على Vercel مع Neon أو Supabase

1. أنشئ قاعدة PostgreSQL. في Neon/Supabase استخدم رابطاً pooler لـ`DATABASE_URL` إن كان مناسباً للتطبيق، ورابط اتصال مباشر لـ`DIRECT_URL` لأوامر Prisma.
2. أضف متغيرات `.env.example` إلى إعدادات مشروع Vercel لكل بيئة (Production وPreview). استخدم سر جلسة مختلفاً وقوياً لكل بيئة، واضبط `NEXT_PUBLIC_SITE_URL` على عنوان البيئة الفعلي.
3. قبل استقبال الزيارات، شغّل محلياً أو من مهمة تشغيل آمنة:

   ```bash
   npm run db:push
   npm run db:seed
   ```

   تأكد أن `DIRECT_URL` يشير إلى قاعدة البيئة المقصودة. افصل قواعد Preview عن Production.
4. اربط GitHub بمشروع Vercel ثم انشر. تحقق من متغيرات البيئة، سجلات البناء، `/robots.txt`، و`/sitemap.xml`.
5. سجّل الدخول إلى `/admin`، غيّر بيانات الوصول الافتراضية، وتحقق من أسعار التوصيل والمخزون قبل فتح المتجر للعملاء.

عند تعديل المخطط استخدم `npm run db:push` على بيئة التطوير، واختبر التغيير قبل تطبيقه على قاعدة الإنتاج. احتفظ بنسخ احتياطية قبل تغييرات البيانات.
